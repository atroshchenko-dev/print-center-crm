# CRM Print

[![CI](https://github.com/atroshchenko-dev/print-center-crm/actions/workflows/ci.yml/badge.svg)](https://github.com/atroshchenko-dev/print-center-crm/actions/workflows/ci.yml)

CRM для університетського центру оперативної поліграфії: замовлення від підрозділів і комерційних клієнтів, каса та зміни, склад витратних матеріалів, ліміти підрозділів і звітність. Система працює у виробництві й покриває всі процеси департаменту.

Інтерфейс українською. Код, коментарі та тести англійською.

## Можливості

- **Замовлення.** Внутрішні (від підрозділів університету, з підписантом і центром витрат) і комерційні. Конструктор послуг з каскадними опціями, ціноутворення на сервері, знімок послуги в JSONB, історія статусів, оптимістичне блокування.
- **Погодження електронною поштою.** Підписант отримує лист із підписаним посиланням, погоджує або відхиляє замовлення без входу в систему.
- **Каса та зміни.** Відкриття й закриття зміни, ранкові показники лічильників обладнання, журнал каси лише на дописування (оновлення й видалення заборонені тригерами PostgreSQL).
- **Склад.** Облік за середньозваженою собівартістю, автоматичне списання за замовленнями, облік заправки картриджів, порадник закупівель на 30/60/90 днів.
- **Ліміти.** Місячні пули груп підписантів і контроль перевищення.
- **Звіти.** Аналітика лічильників, звірка, експорт у XLSX, публічний прайс-лист.
- **Доступ.** Ролі (адміністратор, виконавець, менеджер) і права за модулями, журнал аудиту, захист від самопідвищення прав.
- **Персональні дані.** Політика зберігання й нічне знеособлення: [docs/PII.md](docs/PII.md).
- **Сповіщення.** Telegram-бот для робочої групи й окремої групи погоджень.

## Швидкий старт

```bash
git clone https://github.com/atroshchenko-dev/print-center-crm.git
cd print-center-crm
composer install
npm install

cp .env.example .env
php artisan key:generate
# у .env вкажіть DB_* (PostgreSQL), за потреби REDIS_* і MAIL_*

php artisan migrate --seed

npm run dev          # Vite
php artisan serve    # http://localhost:8000
```

Демо-вхід після `--seed`: `admin@crm.local` / `password`.

## Тести

```bash
php artisan test     # PHPUnit: unit і feature (потрібен PostgreSQL)
npm run test:vue     # Vitest: компоненти Vue
npm run e2e          # Playwright: наскрізні сценарії
vendor/bin/phpstan analyse
```

## Структура

```
app/
├── Console/Commands/   консольні команди: перевірка резервних копій, знеособлення, імпорт архівних замовлень
├── Enums/              статуси й типи як PHP enums
├── Exports/            вивантаження у XLSX
├── Http/               контролери, middleware, FormRequest-валідація
├── Models/             Eloquent-моделі
├── Observers/          спостерігачі замовлень
└── Services/           бізнес-логіка: ціни, склад, каса, ліміти, Telegram
resources/js/
├── Components/         конструктор послуг, UI-компоненти
├── Layouts/
└── Pages/              сторінки Inertia
tests/                  PHPUnit
resources/js/tests/     Vitest
e2e/                    Playwright
```

## Архітектурні правила

1. **Тільки Inertia.js:** без окремого REST API.
2. **М'яке видалення** для довідників і замовлень; журнали (каса, аудит, рух складу, показники лічильників, історія статусів) лише на дописування.
3. **Знімки в JSONB:** замовлення зберігає послугу такою, якою вона була в момент оформлення.
4. **UTC у базі,** `Europe/Kyiv` лише в інтерфейсі й планувальнику.
5. **Enums** замість рядкових статусів, **FormRequest** замість валідації в контролерах.

## CI/CD

GitHub Actions на кожен push і pull request: PHPUnit з покриттям, Vitest, збірка фронтенду, PHPStan, Pint для змінених файлів, `composer audit`, `npm audit`, окремо Playwright E2E.

Розгортання: webhook GitHub після зеленого CI викликає `deploy.sh` (оновлення коду, залежності, міграції, збірка, кеші, перезапуск черги). Якщо крок падає, виконується відкат і надсилається сповіщення в Telegram.
